# 《缀》游戏规划（垂直切片版）

> 版本 **v0.4**｜2026-11-17 修订｜引擎 Godot 4.7｜目标：20–30 分钟可玩垂直切片
>
> **v0.4 变更**：按用户要求「**像素 ×1.5，但保持 Q 版比例**」，内部分辨率从 320×180 升到 **480×270**，主角从 32px 升到 **48px**，**Q 版头身比完全不动（2.5 头身，头占 40%）**。
> 换算极简单：v0.3 全部数值 **×1.5**，因为比例关系未变，手感曲线不用重新调。
> **代价**：1280÷480 = 2.667 非整数，窗口改成 **1440×810（3× 整数）**。
>
> **历史版本**：v0.1 手绘赛璐璐 @1280×720 → v0.2 精细像素 @640×360 → v0.3 Q 版粗像素 @320×180 → **v0.4 Q 版中粗像素 @480×270**

## 一、一句话定位

**可爱二次元风格的 Q 版像素横版类银河恶魔城动作游戏——主角用「线」与「针」战斗，每一次变强都是学会一种新的「缝法」，而每一种缝法都在改写地图本身。**

「缝」同时是战斗词汇和地图词汇，这是本作和普通银河城最大的区别：能力不是「钥匙」，而是「可以改造地形的工具」。

---

## 二、核心循环

```
探索未知区域 ──► 遇到过不去的地形（裂缝 / 断桥 / 高悬锚点 / 缝合墙）
      │                        │
      │                        ▼
      │              记下它，继续走能走的路
      │                        │
      ▼                        ▼
打一场漂亮仗 / 摸到隐藏房 ──► 获得新「缝法」
                               │
                               ▼
                    回头看：那些地形现在能过了
                               │
                               ▼
                    地图连通性改变 → 出口变多 → 回到「探索」
```

20–30 分钟的切片里，这个循环必须跑满 **两圈**，让玩家亲自体验到「我变强了，世界变了」。

## 三、主角与主题

**主角「织」（Ori）**：16 岁，齐耳薄荷绿短发 + 呆毛，琥珀色眼睛，奶白与青绿短披肩、荷叶边白衬衣、深色短裤、超大露指手套、粗跟短靴，腰侧挂一枚卷线轴，手持形似刺绣针的细剑。

她不是战士，是**缝补这个世界的人**。故事基调走「温柔但有一点忧郁」——月夜、古神社、被遗落的器物化作的妖怪。「可爱」不来自卖萌台词，来自**她对这些妖怪的态度**：打败它们之后会替它们把破损的地方缝好。

### 差异化卖点（三条，全部围绕「缝」）

1. **能力即地形改造**：缝合出的平台是真实物理体，能站、能挡弹道、能被 BOSS 撞碎。
2. **战斗是「穿针引线」**：连段不是按键数，是「线的走向」——起手、贯穿、收线三段，收线伤害最高。
3. **赛璐璐硬边光影**：全场景两级明暗 + 粗描边，灯笼暖光与月夜冷光对撞。

## 四、动作内核（手感优先，这是动作游戏的命）

### 4.1 移动

> **数值基准（v0.4）**：内部 **480×270**，**主角 48px 高（Q 版 2.5 头身）**。下列数值单位是**游戏像素/秒**，引擎里直接填。
>
> **×1.5 换算规则很简单**：v0.3 的 320×180 / 32px 全部数值 **×1.5** 即可，因为 Q 版比例、屏高占比、瓦片比例关系完全没变。这是「等比放大」而非「重新调参」，所以手感参数（Coyote、缓冲、速度曲线）一个都不用重新思考。

| 项目 | 值 | 说明 |
|---|---|---|
| 跑速 | **144 px/s** | 3 身位/秒；屏宽 480，横穿一屏 3.3 秒（与 v0.3 完全一致） |
| 加速度 | **1350 px/s²** | 约 0.107s 到满速（手感参数不变） |
| 松手减速度 | **1650 px/s²** | 立刻停，响应优先于物理真实 |
| 重力 | **1350 px/s²** | |
| 上升重力倍率 | 0.82 | 手感更「飘」 |
| 下落重力倍率 | 1.15 | 落地更「脆」 |
| 最大下落速度 | **570 px/s** | |
| 跳跃初速 | **−398 px/s** | 顶点高度约 **58.5px**，占屏高 21.7%（与 v0.3 一致） |
| Coyote Time | **0.10 s** | 离开平台后仍可跳（时间参数永远不变） |
| 跳跃缓冲 | **0.12 s** | 落地前按跳会自动补跳（同上） |
| 二段跳 | 获得「引线」后解锁 | 初速 0.9 倍 |

**为什么跳跃占比是 21.7%（高于原始方案的 15%）**：Q 版角色腿短、头大，视觉重心高。如果沿用 15% 屏高，跳跃会显得"黏在地上"。粗像素游戏的通行做法是**让跳跃更夸张**——《铲子骑士》的跳跃高度接近角色身高的 1.5 倍。这个判断在 ×1.5 后依然成立，所以直接继承。

**这三条（Coyote / 缓冲 / 松手减速）是「操作感觉很爽」的全部秘密，第一周就要调到闭眼舒服。**

### 4.2 战斗

- **轻击**：三段连招，0.22s / 0.20s / 0.32s，第三段「收线」位移前冲 **18px**。
- **重击**：蓄力 0.35s，霸体，破防。
- **完美闪避**：受击前 0.12s 内闪避 → 0.6s 子弹时间，可以取消进任何攻击。
- **弹反（挑针）**：把敌方投射物用针挑回去，造成双倍伤害。这是二次元动作游戏最爽的一招，BOSS 战必须依赖它。
- **受击**：非无敌，但有 0.9s 硬直 + 击退；玩家血量 5 颗心，恢复靠存档点。

**打击感四件套（缺一不可）**：顿帧 0.06s / 屏幕震动 **2px·0.08s**（480×270 下 1 像素显示为 3 屏像素，震幅可以回到 2px）/ 命中粒子 + 白闪 2 帧 / 命中音效跟手。

> **Q 版专属手感补偿**：角色小、动作幅度天然小，所以**受击反馈必须更夸张**——击退距离 15px，受击时角色整体闪烁 3 帧。这是 Q 版动作游戏能"打起来有感觉"的关键。

### 4.3 五种「缝法」= 五次能力解锁（切片只做前两个）

| 能力 | 作用 | 地图门控 | 战斗用途 |
|---|---|---|---|
| **引线** | 朝锚点发射丝线，拉自身过去 | 高处锚点、跨深渊 | 位移闪避、拉近敌人 |
| **缝缀** | 把两个「线头」缝起来，生成可站立平台 | 断桥、悬空裂缝 | 把敌人缝在地上、封路 |
| **解线** | 反向拆线，解除被「缝住」的物体 | 堵路的缝合墙 | 拆敌人护甲 |
| **剪断** | 居合突进 + 切断 | 切断悬吊机关的绳 | 高伤害突进，穿过伤害判定 |
| **回针** | 回溯 2 秒前的位置 | 唯一能穿过「消失的光门」 | 终极保命，二段解谜 |

切片做 **引线 + 缝缀** 两个，足以支撑「两圈循环」。

## 五、垂直切片的内容边界

**区域：苔庭·月亮回廊（Moonlit Cloister）**

- 12 个房间，单房间 **960×540 游戏像素**（2 屏宽 × 2 屏高），纵向 2 层
- 存档点 2 处（灯笼龛，坐上去恢复 + 存档）
- 小怪 4 种：苔团（近战）、灯笼虫（飞行弹幕）、石守（需弹反破甲）、线偶（会抓人）
- **区域 BOSS：瓷面的守夜人**（三阶段，第二阶段起必须用弹反）
- 隐藏房 1 个（用缝缀打开）
- 收尾钩子：打完 BOSS 露出一条进不去的竖井，切片在「下次一定」的位置结束

**目标体验时间：22 分钟**（首通），通关后地图显示「已探索 68%」——留白的钩子比全收集更勾人。

## 六、BOSS 设计：瓷面的守夜人

| 阶段 | 血量 | 核心机制 | 玩家要用的能力 |
|---|---|---|---|
| P1 | 100%–66% | 六臂挥击 + 地面裂纹，慢速可读 | 闪避、三段连 |
| P2 | 66%–33% | 浮空，扔「碎片弹幕」——**必须弹反回去**才能打进硬直 | 弹反（唯一解） |
| P3 | 33%–0% | 场地被撕裂，**用缝缀把断桥缝回来**才有立足点 | 缝缀（能力检验） |

设计要点：BOSS 战是**能力的考试**，不是数值的考试。P2 和 P3 各考一个能力，玩家打不过就说明能力没学透——这是最好的教学。

## 七、美术规格（像素 + 赛璐璐配色逻辑）

> 完整规范见 [02-像素美术规范.md](02-像素美术规范.md)，本节只留要点。

### 7.1 风格铁律

1. **每个部件严格 2 色**（亮色 + 深一阶的暗色），阴影边缘 1px 硬切，**禁止渐变**。
2. **外轮廓 1px 描边，颜色用 `#12142A` 而非纯黑**——纯黑描边是像素画的常见败笔，会让画面死板。
3. **唯一允许的柔光**是灯笼的暖色辉光（3 色同心扩散），全画面唯一「软」的东西。
4. **光源锁死左上**，高光在左上、阴影在右下，全项目不许有例外。

### 7.2 色板（28 色硬上限）

完整 28 色表见 [02-像素美术规范.md](02-像素美术规范.md) 第三节。核心几个：

| 用途 | 色值 |
|---|---|
| 描边 / 深渊 | `#12142A` |
| 夜色远 / 中 | `#1B2244` / `#2A3A63` |
| 苔中 / 暗 / 亮 | `#4A6B4F` / `#2E4634` / `#6E9A6B` |
| 石中 / 暗 / 亮 | `#5A6478` / `#394051` / `#7B8699` |
| 月光高光 | `#8FD3E8` |
| 灯笼亮 / 中 / 暗 | `#FFE9A8` / `#FFC46B` / `#E0913F` |
| 主角披肩亮 / 暗 | `#F2F8EC` / `#C4D8C2` |
| 发色亮 / 暗 | `#A8E8C6` / `#5FA882` |
| 危险 / 弹幕 | `#FF7A9C` |

### 7.3 分辨率与技术选型（v0.3：Q 版粗像素）

> **本节已被 [02-像素美术规范.md](02-像素美术规范.md) 取代。** 当前决策：**Q 版像素 @480×270，3× 放大到 1440×810**。

- **内部 480×270，整数 3× 放大到 1440×810**（1080p 屏可 4× 到 1920×1080），最近邻采样，关闭抗锯齿，**锁定整数缩放**。
- 主角高 **48px（Q 版 2.5 头身，头 19px）**，BOSS 高 144px。
- 瓦片尺寸 **12×12**，标准平台厚 6px。
- 色板收缩到 **28 色硬上限**，禁止纯黑描边。
- 背景三层视差：0.2× / 0.5× / 0.8×，各层做轻微上下浮动。
- 前景一层（草叶、垂落的紫藤）做遮挡，0.95× 视差。

### 7.4 角色动画方案：**像素逐帧手绘**（原「骨骼绑定」作废）

像素 → 骨骼绑定会破坏像素网格，尤其是旋转会让像素边缘错位，**这是硬性冲突，不能两全**。所以动画方案改为逐帧：

- 主角 48px 高（Q 版），全套动作约 **44 帧**（帧数不因分辨率提高而增加），一个人 **2–2.5 周**可完成。
- 帧预算明细见 [02-像素美术规范.md](02-像素美术规范.md) 第五节。
- **AI 生图不得用于角色与动画帧**——实测 AI 出的「4 帧行走分解」只是轻微位移，不是真实步态；且 AI 图的像素颗粒密度与手绘图对不上。AI 仅用于概念稿与远景视差打底。

### 7.5 Q 版比例与辨识度（v0.3 新增）

粗像素 Q 版最大的坑是**动作看不清**（身体短、手臂短）。三条硬补偿，写进规范：

1. **武器比人显眼**：针剑长 **33px**（身高的 0.7 倍），挥砍画 **5–6px** 粗的 `#FF7A9C` 弧线。
2. **头部跟随动作**：攻击时头部整体前倾 **3px**，比手臂动作更能读出"在打"。
3. **蓄力与命中必须有颜色变化**：蓄力武器变 `#B9F2FF`，命中瞬间全屏 1 帧白闪。

详见 [02-像素美术规范.md](02-像素美术规范.md) 第三节 3.3。

## 八、素材获取策略（按你选的「先找现成」）

### 8.1 先找现成（像素化之后，能买的变多了）

改成精细像素后，素材市场从「几乎没有」变成「主流品类」——像素素材在 itch.io 上大量存在且多数带商用授权。检索关键词：

| 类型 | 用途 | 检索关键词 |
|---|---|---|
| **场景瓦片包** | 地形、装饰 | `pixel art metroidvania tileset`、`pixel art shrine forest` |
| **角色 / 杂兵** | 小怪、NPC | `pixel art platformer character anime`、`16x16 character pack` |
| **视差背景** | 远景三层 | `pixel art parallax background night` |
| **特效包** | 命中、弹幕、丝线 | `pixel art vfx slash impact` |

参考入口：[itch.io 平台游戏素材](https://itch.io/game-assets/top-rated/genre-platformer/tag-2d/tag-asset_pack/tag-characters)、[Metroidvania 标签素材](https://itch.io/game-assets/new-and-popular/tag-2d/tag-asset-pack/tag-metroidvania/tag-sprites)。

**授权红线**：一定要确认 **Commercial Use** 允许，且允许修改。CC0 / CC-BY 最稳；「免费版」通常禁止商用。

**买来之后必须做的一步**：量化到本项目 28 色板，否则色板铁律失守。用 Aseprite 的 Replace Color 批量处理，全套约 10 分钟。

### 8.2 AI 生图的正确位置（像素化后大幅收窄）

已生成三张风格锚定图（见 `art/concept/`）：

- `01-heroine.png` — 手绘赛璐璐版主角（**已作废，仅留作设计参考**）
- `02-shrine-garden.png` — 区域氛围图（**右下角有 AI 生成水印**，且是手绘风，仅作氛围参考）
- `03-heroine-pixel.png` — **像素版主角，当前风格锚点**（含全身立绘 + 头部特写 + 4 帧行走分解）

**从 03 这张图实测得到的结论**（很关键，直接影响排期）：

| 观察 | 结论 |
|---|---|
| 像素密度、配色、深色描边符合规范 | ✓ 风格锚定成功，可作配色与比例依据 |
| 下方 4 帧行走分解几乎完全一致，只有轻微位移 | ✗ AI 出不了真实步态，**动画帧必须自己画** |
| 剑柄与手掌之间有缝隙，武器悬浮 | ✗ AI 不懂部件对齐，**角色素材必须手修** |

**因此 AI 的合法用途只有两条**：

1. **概念稿与氛围参考**——定构图、定光、定配色方向。用完即弃，不进游戏。
2. **大面积远景视差打底**——AI 出图 → 降采样到 480×270 → 强制量化到 28 色 → 手修细节。远景没人盯着看，容错高。

**AI 绝对不碰**：角色、BOSS、动画帧、UI 图标。这些一帧一风格，全盘崩。

**已知限制**：本机 Google Gemini 的 key 没配（`generate_image` 会直接报错），目前走的是 WorkBuddy 的 `hunyuan-image-alpha`，出图带水印。若后续要频繁出概念稿，建议配好 Gemini key。

### 8.3 素材风格统一的三条纪律

1. **色板量化**：所有进项目的美术资源，一律先量化到 28 色板。
2. **描边统一 1px**，颜色用 `#12142A`（同色系深色），**禁止纯黑**。
3. **光源锁死左上**，高光在左上、阴影在右下，全项目不搞例外。

## 九、技术方案（Godot 4.7）

### 9.1 项目结构

```
actGame/
├── project.godot
├── art/
│   ├── concept/            # 概念稿（不进游戏）
│   ├── characters/ori/     # 主角逐帧图集（48px 高，Q 版）
│   ├── tilesets/           # 16×16 瓦片，已量化到 28 色
│   ├── bg/                 # 三层视差
│   ├── vfx/                # 命中/弹幕/丝线特效
│   └── palette.gpl         # 28 色板（Aseprite 可直接导入）
├── audio/
├── src/
│   ├── autoload/           # GameState / Audio / SceneRouter / SaveSystem
│   ├── player/             # Player.tscn + 状态机
│   ├── enemies/
│   ├── boss/
│   ├── abilities/          # ThreadPull / Stitch
│   ├── world/              # Room / RoomManager / SavePoint
│   └── ui/
├── scenes/
│   ├── main_menu.tscn
│   ├── rooms/              # 12 个房间场景
│   └── levels/moonlit_cloister.tscn
└── docs/
```

### 9.2 关键技术点

| 系统 | 方案 |
|---|---|
| 角色控制 | `CharacterBody2D` + 自写状态机（枚举 + 状态对象，不上插件） |
| 动画 | `AnimatedSprite2D` + `SpriteFrames`（逐帧，**不用 Spine**） |
| 地图 | `TileMapLayer`（4.3+ 新节点），**12×12 格**，`snap_2d_*` 必开 |
| 房间切换 | `Area2D` 触发 → `RoomManager` 淡入淡出加载下一个房间 |
| 描边 | **不需要 shader**——像素画的描边是画在图里的 1px 深色像素 |
| 赛璐璐质感 | **不需要 shader**——靠色板与 2 档阴影贴图实现，运行时零开销 |
| 像素对齐 | `snap_2d_transforms_to_pixel` + `snap_2d_vertices_to_pixel` + **`stretch/scale_mode = integer`**（三个都必须开） |
| 相机 | 自写 `Camera2D`，位置取整到像素，带 deadzone 与前瞻 |
| 存档 | JSON 存进 `user://save.json`，存房间 id + 位置 + 已获能力 + 已探索集合 |
| 输入 | `InputMap` 手柄优先，键鼠映射同时支持 |

> **顺带的好处**：改成像素后，原方案里最麻烦的两个 shader（屏幕空间描边、亮度量化）直接不需要了——它们是手绘赛璐璐为了"做出线条感"才需要的，像素画天生自带。这砍掉了约一周的美术技术攻关。
>
> **v0.4 注意**：480×270 显示时 **1 个游戏像素 = 3 个屏幕像素**（1440×810 窗口），任何"半像素"的位移都会肉眼可见地抖。相机、角色、UI 位置一律取整。

## 十一、风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 逐帧动画工作量被低估 | 拖到 6 周以上 | 切片只做 44 帧；W2 中段未完成则先用色块占位，美术补到 W4 |
| **Q 版动作看不清** | 打击感消失，动作游戏废掉 | 三条硬补偿：武器比人显眼（剑 33px）、头部跟随动作（前倾 3px）、蓄力命中变颜色（见 7.5） |
| AI 素材不能用（网格是假的） | 误以为能省美术 | 已明确分工：AI 只做概念稿与远景视差，角色一律手绘 |
| **AI 出的角色图与场景图颗粒密度不一致**（v0.4 新增） | 同屏出现立刻"缝合感" | 以角色图密度为准，场景图降采样到 480×270 再整数放大，拉齐颗粒后量化 |
| 买来的素材瓦片是 16×16 | 与 12×12 不成整数倍，需重绘 | 优先找 12×12 或可裁边的包；否则降采样到 12×12 |
| 像素网格抖动（半像素位移） | 1 像素=3 屏像素，抖动明显 | `snap_2d_*` 两项 + `scale_mode = integer` 三个都必开 |
| **480×270 到 720p 非整数倍**（v0.4 新增） | 像素大小不均，画面发虚 | 窗口用 1440×810（3×），全屏 1080p 用 4×；绝不直接铺 1280×720 |
| 关卡设计耗时 | 房间连通性反复推翻 | 先用白盒 + 一张手绘拓扑图，跑通两圈循环再上美术 |
| 手感调不出来 | 项目失败的最大原因 | W1 全部预算砸手感，内容量延后 |
