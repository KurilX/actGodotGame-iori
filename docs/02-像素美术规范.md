# 像素美术规范 v0.4

> 变更日期 2026-11-17｜从「手绘赛璐璐」→「精细像素」→「Q 版粗像素」→ **「Q 版中粗像素」**
>
> **v0.4 变更**：按用户要求「像素 ×1.5，但保持 Q 版比例」，内部分辨率从 320×180 升到 **480×270**，主角从 32px 升到 **48px**，**Q 版头身比完全不动（2.5–3 头身，头仍占 40%）**。
> 连带重算：运动数值、瓦片尺寸、房间尺寸、帧预算。
> **注意**：×1.5 让放大倍率变成非整数（1280÷480 = 2.667），需要特殊处理，见 2.3 节。

---

## 一、为什么要改，以及改了什么

**判断：改成像素是对的，而且不止是"方便"，它解决了原方案三个真实风险。**

| 原方案（手绘赛璐璐） | 像素 | 为什么像素更稳 |
|---|---|---|
| AI 生图风格易漂移，同一角色两次生出不同脸 | 调色板量化会吃掉大部分漂移 | **这是"稳定"的核心**：把 28 色限定死，AI 图再漂也被强行拉回同一套颜色 |
| 逐帧动画要 200+ 张，一个角色几周 | 角色只有 48px，一套动作约 44 帧 | 单帧工作量小两个数量级，改设计不心疼 |
| 二次元赛璐璐素材包几乎买不到 | 像素素材包在 itch.io 海量且有商用授权 | 杂兵、道具、地形可以直接买现成 |
| 粗描边 + 柔光，观感贵但难统一 | 1px 硬描边，规则可机械执行 | 统一靠规则，不靠美术师手感 |

**v0.4 让掉的东西，必须提前知道**：48px 的 Q 版角色**做不出赛璐璐的"质感"**——没有荷叶边的细节、没有发丝走向、没有渐变阴影。换来的是**表情与体态的可爱**。这是拿"精致度"换"亲和力"，是主动取舍，并非妥协。

**这仍然不是 RPG Maker 那种像素**（你之前明确排斥的）。区别在**视角与构图**：RPG Maker 是 16×16 俯视格子、角色站在地图上；本作是**横版动作、48px 角色、屏幕高 270 格**，观感接近《铲子骑士》《蔚蓝》的粗像素质感，但配色走二次元。

## 二、像素尺度（最关键的一个数）

### 2.1 定稿：内部 480×270，Q 版比例不变

| 项目 | v0.3（32px 版） | **v0.4（定稿）** |
|---|---|---|
| 内部分辨率 | 320 × 180 | **480 × 270** |
| **主角身高** | 32 px | **48 px** |
| 头身比 | 2.5 头身（头 13px） | **2.5 头身（头 19px）** ← 比例完全不变 |
| 主角宽（含披肩） | 20 px | **30 px** |
| BOSS 身高 | 96 px | **144 px**（占屏高 53%，占比不变） |
| 瓦片尺寸 | 8 × 8 | **12 × 12** |
| 标准平台厚 | 4 px | **6 px** |
| 单房间 | 640 × 360 | **960 × 540**（2 屏宽 × 2 屏高） |
| 占屏高比例 | 17.8% | **17.8%**（不变） |

**核心原则：这不是放大重画，是同一套构图等比 ×1.5。** 头身比、屏高占比、瓦片与角色的比例关系全部保持原样，只是像素颗粒变细、角色变大。

### 2.2 为什么 ×1.5 是对的

v0.3 定在 32px 时，Q 版的脸只剩 10px 宽，眼睛只能用 4×4 的极简结构。**×1.5 之后脸宽 15px，眼睛可以做到 6×6，能画出瞳孔和 1px 高光两个层次**——这是"更耐看"的实质收益，而不只是变大。

| 指标 | 32px 版 | 48px 版 | 变化 |
|---|---|---|---|
| 脸宽 | 10 px | 15 px | 眼睛结构从「符号」升级到「可读」 |
| 眼睛尺寸 | 4 × 4 | 6 × 6 | 能放瞳孔 + 高光 |
| 剑长 | 22 px | 33 px | 挥砍轨迹更舒展 |
| 单帧面积 | 640 px² | 1440 px² | 作画量 ×2.25 |

### 2.3 致命细节：480×270 放大到 720p 不是整数倍

**这是 ×1.5 唯一的坑，必须处理，否则画面会糊。**

`1280 ÷ 480 = 2.667`，不是整数。直接全屏放大，像素会被不均匀拉伸（有的像素 2 屏幕像素宽、有的 3），观感立刻崩。

**三种解法，推荐第一种**：

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 窗口 1440×810（推荐）** | 480×270 整数 3× 放大 | ✓ 完美整数倍，像素锐利。1440×810 在 1080p 屏上窗口化无压力 |
| B. 黑边锁 2× | 只放大 2× 到 960×540，四周留黑边 | ✓ 整数但画面偏小，浪费屏幕 |
| C. 1080p 全屏 4× | 480×270 放大 4× = 1920×1080 | ✓ 全屏整数倍，但要求玩家有 1080p 屏 |

**定稿方案**：Godot 设 `stretch/scale_mode = integer`，窗口默认 **1440×810**（3×），玩家全屏时自动选 4×（如果屏幕够 1080p）或退回 3× 加黑边。**整数缩放的铁律不能破**——这是像素游戏观感的底线。

### 2.4 不设更细的备选

如果实机觉得 48px 太大，可以退到 **384×216 / 主角 38px**（1280÷384 = 3.33，仍需整数缩放方案）。但**不建议再往细走**：再细就接近 v0.2 的 52px，回到"像素感偏弱"的老问题。

## 三、Q 版比例规范

粗像素与 Q 版是天然搭配，但**Q 版会吃掉动作游戏的辨识度**，必须用规则补回来。

### 3.1 身体比例（主角，总高 48px）

| 部位 | v0.3 (32px) | **v0.4 (48px)** | 说明 |
|---|---|---|---|
| 头（含头发） | 13 px | **19 px** | 占全身 40%，Q 版核心 |
| 躯干 | 8 px | **12 px** | |
| 腿 | 9 px | **13 px** | |
| 脚（靴子） | 2 px | **4 px** | |
| **合计** | 32 px | **48 px** | 2.5 头身，比例不变 |

### 3.2 脸部放大规则：**眼睛 6×6**

48px 身高下脸宽 15px，眼睛从 4×4 升级到 **6×6**：

```
瞳孔 4×4 + 白色高光 1px（左上角）+ 上眼睑 1px 深色 + 下眼睑 1px 浅色
```

**双眼间距严格 4px**（原 3px × 1.5 取整），这个数一旦乱，脸部立刻崩。全项目所有角色脸都走同一模板。

### 3.3 动作辨识度补偿（关键，别跳过）

Q 版身体短、手臂短，**攻击动作容易看不清**。三条硬补偿（数值按 ×1.5 更新）：

1. **武器必须比人还显眼**：针剑长度 = **33px**（身高的 0.7 倍），挥砍时用最高饱和色 `#FF7A9C` 画一个 **5–6px** 粗的弧形轨迹。
2. **头部跟随动作**：攻击时头部整体前倾 **3px**，比手臂动作更能让人读出"在打"。
3. **蓄力与命中必须有颜色变化**：蓄力时武器变 `#B9F2FF`（丝线光），命中瞬间全屏 1 帧白闪。

### 3.4 禁止事项

- **禁止加细节**：画到"能认出来"就停，48px 下多加装饰会脏。
- **禁止用抗锯齿**：所有边缘硬切。
- **禁止用超过 2 级的阴影**：Q 版角色体积小，3 级明暗会脏。

## 四、色板（28 色，硬上限）

### 3.1 铁律

- **总色数 ≤ 28**，谁都不许私自加色。新颜色必须从现有色里调，或提出替换。
- **禁用纯黑 `#000000` 描边**，改用同色系深色——纯黑会让画面死板，这是像素画的常识错误。
- **不做抗锯齿**，所有边缘必须硬切。
- **抖动（dithering）只允许用在大面积渐变**（天空、水面、远景雾），前景一律纯色块。

## 四、赛璐璐怎么落到像素上

原方案的赛璐璐四要素，在像素里的对应做法：

| 赛璐璐要素 | 像素实现 |
|---|---|
| 平涂大色块 | 直接就是纯色块，不需要额外处理 |
| 两级明暗 | 每个部件固定「亮色 + 暗色」两档，阴影边缘 1px 硬切 |
| 粗描边 | 外轮廓 1px 深色（用 01 或 02），内部分界线更浅或不画 |
| 柔光唯一来源 | 灯笼暖光用「亮—中—暗」3 色同心扩散 + 半透明叠加层（Godot 里用 Light2D 或贴图叠加） |

**关键技巧：光源方向锁死左上**。所有高光在左上、阴影在右下，全项目不许有例外。这一条比任何调色都更能保证统一。

## 五、动画帧预算（逐帧手绘，现在可行了）

### 5.1 主角「织」（48px 高，Q 版）

48px 的 Q 版角色，单帧面积比 32px 版大 2.25 倍，但**细节容错也提高了**——48px 下画错 1 像素没 32px 下那么刺眼，返工成本反而降低。

| 动作 | 帧数 | 说明 |
|---|---|---|
| 待机 | 4 | 呼吸 + 呆毛轻摆，循环 |
| 跑 | 6 | 2 个完整步态循环（Q 版腿短，6 帧够用） |
| 起步/急停 | 2+2 | 容易漏，但对手感贡献很大 |
| 跳（起/升/降） | 3 | |
| 落地 | 2 | |
| 轻击 1/2/3 | 3+3+4 | 第三段收线多 1 帧 |
| 重击蓄力/释放 | 3+4 | |
| 闪避 | 3 | |
| 受击 | 2 | |
| 死亡 | 5 | |
| **合计** | **约 44 帧** | 一个人 **2–2.5 周**可完成 |

**帧数沿用 44 帧没有增加**——分辨率提高不等于帧数要加，Q 版动作的"少帧 + 大位移"逻辑在 48px 下同样成立。增加的是**单帧作画时间**（面积 ×2.25）。

### 5.2 杂兵与 BOSS

- 4 种杂兵：**统一 36px 高**（主角的 0.75 倍，保持主角存在感），各 8–12 帧。
- BOSS（**144px**）：约 50–70 帧，是切片里最重的一块。144px 在 480×270 里占屏高 53%，压迫感足够。

### 5.3 一个反直觉的收益

Q 版像素下，**动作可以用"少帧 + 大位移"**：比如挥剑只画 3 帧，但第 2 帧手臂幅度夸张。这既节省工作量，又比精细像素的 5 帧更有冲击力——《铲子骑士》就是这么做的。

## 六、素材策略（像素化之后变化很大）

### 6.1 好消息：能买的变多了

像素素材在 itch.io 上是主流品类，且大量 **CC0 / 商用授权**。检索关键词：

```
pixel art metroidvania tileset 12x12 / 16x16
pixel art platformer character chibi
pixel art vfx slash impact
pixel art parallax background forest shrine
```

参考入口：[itch.io 平台游戏素材](https://itch.io/game-assets/top-rated/genre-platformer/tag-2d/tag-asset_pack/tag-characters)、[Metroidvania 标签素材](https://itch.io/game-assets/new-and-popular/tag-2d/tag-asset-pack/tag-metroidvania/tag-sprites)。

**注意两条**：

1. **买来的素材必须量化到我们的 28 色板**，否则色板铁律失守（Aseprite 的「Replace Color」批量做，10 分钟）。
2. **瓦片尺寸要统一到 12×12**（v0.4 从 8×8 上调）。市面上主流是 16×16，与 12×12 不成整数倍，**需要重绘或裁边**——这是 ×1.5 带来的一个隐性成本，买素材时要留意有没有 12×12 的包。

### 6.2 坏消息：AI 生图不能直接当素材用

AI 出的"像素风"图，**像素网格是假的**——放大看每个"像素"大小不一、边缘带抗锯齿，直接塞进 480×270 网格会脏。

**AI 的正确位置（只做两件事）**：

1. **出概念稿与氛围参考**——定构图、定光、定配色方向。
2. **大面积背景打底**——远景视差层可以 AI 出图 → 降采样到 480×270 → 强制量化到色板 → 手修细节。远景容错高。

**AI 绝对不要碰**：角色、BOSS、动画帧、UI 图标。

> **v0.4 实测（重要）**：`art/concept/07-shrine-garden-pixel.png` 是 AI 出的像素场景图，**颗粒密度明显比 `06-heroine-chibi-48px.png`（角色图）细**。如果两张直接放进同一画面，会立刻暴露"缝合感"。
> **对策**：以角色图的颗粒密度为准，场景图**降采样到 480×270 再放大回去**，用整数倍缩放把颗粒"拉齐"，然后量化到 28 色板。这一步必须做，否则风格不统一。

### 6.3 工具

| 工具 | 用途 | 成本 |
|---|---|---|
| **Aseprite** | 主力画图 + 动画 + 调色板量化 | $20（值得买） |
| **LibreSprite** | Aseprite 免费分叉 | 免费 |
| **Pixelorama** | 备用，Godot 生态，免费 | 免费 |
| **Godot 内置 TileMap 编辑器** | 拼图 | 免费 |

## 七、Godot 工程设置（一次性配好，必须严格）

```
项目设置：
  display/window/size/viewport_width      = 480
  display/window/size/viewport_height     = 270
  display/window/size/window_width_override = 1440
  display/window/size/window_height_override = 810   # 3x 整数放大
  display/window/stretch/mode             = canvas_items
  display/window/stretch/aspect           = keep
  display/window/stretch/scale_mode       = integer       # 关键：禁止非整数缩放
  rendering/textures/canvas_textures/default_texture_filter = 0 (Nearest)
  rendering/2d/snap/snap_2d_transforms_to_pixel = true
  rendering/2d/snap/snap_2d_vertices_to_pixel   = true
  rendering/antialiasing/quality/msaa_2d  = Disabled

纹理导入：
  每张像素图 → Filter = Nearest, Mipmaps = Off, Compression = Lossless
```

**三条必须开，缺一条就翻车**：

1. **`stretch/scale_mode = integer`**（最关键）：480×270 到 1280×720 是 **2.667 倍，非整数**，直接放大会让像素大小不均——有的像素 2 屏像素、有的 3，观感立刻崩。**必须走整数倍**：窗口默认 1440×810（3×），全屏时若有 1080p 屏则用 4×（1920×1080），否则退回 3× 加黑边。
2. **`snap_2d_transforms_to_pixel` / `snap_2d_vertices_to_pixel`**：否则角色会落在半像素位置，网格抖动。这是像素游戏最常见的工程事故。
3. **Nearest 采样**：默认的线性采样会把像素边缘糊掉。

> **v0.4 提醒**：如果坚持窗口必须 1280×720，那就**不要用 480×270**，退回 320×180（4× 刚好整数）。这是「×1.5 颗粒」与「1280×720 窗口」之间的硬冲突，二选一。
