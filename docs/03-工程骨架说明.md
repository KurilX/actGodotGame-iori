# 工程骨架说明（W1 起步）

> v0.2｜2026-11-17｜引擎 Godot 4.7.2｜**已接入行走 / 跳跃 / 落地动画**｜手感待调

## 一句话现状

**能跑、能跳、能打，并且有逐帧动画了。** 10 项冒烟测试仍全绿。

## 怎么运行

```powershell
godot --path .                                                 # 跑游戏（会开窗口）
godot --headless --path . --script tools/verify_headless.gd    # 冒烟测试（无窗口）
godot --path . --script tools/capture.gd                       # 截图（窗口缩到右下角，不抢焦点）
godot --path . --script tools/capture.gd -- --show             # 截图并显示大窗口
```

> **关于「不打扰桌面」**：`capture.gd` 默认把窗口缩成 480×270、无边框、不置顶、放屏幕右下角，
> 且不主动抢焦点。但 Godot 4.7 下**无法做到真正无窗口截图**（三条路都试过，见第 13 条坑），
> 所以调试期间如果用 `capture.gd`，还是会短暂出现一个小窗口。
> **完全静默的验证请用 `verify_headless.gd`**，它只跑逻辑不渲染。

Godot 已通过 `winget install --id GodotEngine.GodotEngine -e` 装好（4.7.2）。
若 `godot` 不在 PATH（winget 非管理员安装时不会建软链），直接用绝对路径：

## 动画系统

### 图集规格

所有动画横排成条，**每帧 48×48，锚点在帧底中心**：

| 文件 | 帧数 | 循环 | 帧率 | 说明 |
|---|---|---|---|---|
| `ori_idle.png` | 4 | 是 | 6 fps | 呼吸起伏 + 头部轻晃 |
| `ori_run.png` | 6 | 是 | 12 fps | 两腿前后交替 + 身体起伏 |
| `ori_jump.png` | 3 | 否 | 8 fps | 上升收腿 / 顶点张开 / 下落伸直 |
| `ori_land.png` | 2 | 否 | 12 fps | 弹压回弹 |

### 动画状态映射

| 游戏状态 | 播放 | 备注 |
|---|---|---|
| IDLE | idle | |
| RUN | run | |
| JUMP（上升） | jump 第 0 帧 | 暂停播放，固定姿势 |
| FALL（下落） | jump 第 2 帧 | 暂停播放，固定姿势 |
| LAND | land | |
| ATTACK / HURT | idle | 攻击动画待补 |

朝向用 `AnimatedSprite2D.flip_h` 翻转，**不翻整个节点**（否则碰撞盒和相机也跟着翻）。

### 动画怎么生成的

`tools/make_animation.py` 从单张 48×48 待机精灵程序化生成，**没有重新画**：

1. 以 y=38 为界切成上段（头+躯干）和下段
2. 下段再按实测列坐标抠出左腿（x5–13）、右腿（x14–21）
3. 每帧分别给两条腿不同的横向位移 + 小幅度抬脚

**为什么不用 AI 出帧**：实测 AI 的「4 帧行走分解」只是整体轻微位移，没有真实步态；且 AI 图的像素网格是假的。

## 开发中真实踩到的坑（记录在此，避免重犯）

### 1. 跳跃初速不能用文档里的 −398

文档按 `v²/(2g) = 398²/(2×1350) = 58.7px` 算顶点高度，但**实际上升期重力乘了 0.82**，真实顶点是 71.5px，比规范高 22%。

**修正**：初速改 **−360**，实测顶点 58.5px，与规范一致。代码里已注明原因。

### 2. 小跳截断只能执行一次

`velocity.y *= 0.45` 如果每帧都跑，上升速度会被持续衰减，跳跃高度几乎归零（实测只有 5.4px）。

**修正**：加 `_jump_cut_done` 标记，只在松开按键的那一帧截断一次。

### 3. 反向移动没有急转加成会"滑冰"

左移测试 30 帧只移动 6.5px——角色要先花 10 帧把 +144 的速度降到 0 才能反向加速。

**修正**：反向输入时加速度乘 `TURN_BOOST = 2.2`。动作游戏必备，否则转向迟钝。

### 4. 抠图必须在量化之前、且要留背景边

两个连环坑：
- **先量化再判断背景**：背景 `(249,247,249)` 会被吸附到色板里的披肩亮 `#F2F8EC`，与角色白色衬衣混在一起，导致背景整片留下变成白方块。
- **裁剪贴边**：flood-fill 的种子点在四角，若角色贴着边缘，种子全落在角色身上，背景清不掉（只抠掉 14 个像素）。

**修正**：在原始 RGB 上做 flood-fill，且裁剪时四周留 4px 纯背景边。现在透明占比 37.1%，衬衣完整保留。

### 5. 拆腿不能靠「找中间空隙」

腿部区域实际有三段：左腿、右腿、以及右侧垂下的剑。按列连通区间切分时，若取「最宽的两段」，会把剑当成右腿（实测切出 28px 宽的"腿"）。

**修正**：按实测像素坐标硬编码左右腿范围（x5–13 / x14–21），x22 以后归入上段随躯干动。

### 6. 裁短腿会让腿"断掉"

最初想用「从顶部裁掉 N 行」来实现抬腿，结果裤子和靴子也被裁掉，腿与身体之间出现空隙，帧 2/5 明显脱节。

**修正**：改为**只做横向位移 + 最多 1px 的上移**，不裁短。抬腿效果靠 `dy` 而非 `cut`。

### 7. `AnimatedSprite2D` 没有 `resume()`

只有 `play()` 和 `pause()`，写 `resume()` 会运行时抛 `Nonexistent function`。要恢复播放就直接 `play()`。

### 8. 朝向翻转要每帧更新

`flip_h` 最初只在 `_sync_animation()` 里设，而 ATTACK/HURT 状态不会走到那里，导致待机转身不生效。**修正**：移进 `_update_state()` 顶部，每帧无条件执行。

### 9. 【最坑】SpriteFrames 里写 `region` 不会裁剪贴图

在 `.tscn` 的 `SpriteFrames` 里这样写：

```
"frames": [{ "texture": ExtResource("2_idle"), "region": Rect2(0, 0, 48, 48) }]
```

**`region` 字段不生效**，整条 288×48 的图集会被当作一整张画出来。表现是画面里并排出现 6 个角色，间隔正好等于帧宽 48px——**这个间隔就是铁证**。

我一开始误判成"窗口残影"，花了很久去查交换链、SubViewport、离屏渲染，全错。**判断方法**：数角色间距，若等于帧宽，就是图集没分帧。

**修正**：用 `tools/split_frames.py` 把图集拆成 15 张单帧 PNG，`SpriteFrames` 每帧引用独立贴图。

### 10. 改动画的正确流程

因为图集和单帧是两套文件，改动画时必须按顺序重跑，否则改动不生效：

```powershell
python tools/make_animation.py      # 1. 重新生成横排图集
python tools/split_frames.py        # 2. 拆成单帧（Godot 读的是 frames/）
python tools/add_contact_shadow.py  # 3. 补脚底接地暗影
godot --headless --path . --import  # 4. 让 Godot 重新导入贴图
```

**只跑第 1 步不会生效**——游戏引用的是 `frames/` 下的单帧，图集只是中间产物。

### 11. 「悬空」其实不是坐标问题，是缺阴影

用户反馈角色看着悬空。实测游戏内坐标：

```
碰撞盒底边 y = 479.99
地面顶部   y = 480
角色脚     y = 479.99
```

**误差 0.01px，几何上完全贴地。** 真正的原因是视觉判读：

1. **没有落地阴影**——人眼判断"接触"靠阴影与接触点变暗，纯靠边缘对齐看着就是飘的。
2. **脚底描边与地面撞色**——脚底那一行是 `#7B8699`（石亮），地面草皮是 `#6E9A6B`（苔亮），两者亮度接近，相接时读不出"踩在上面"，反而像"融进地面"。

**修复两条**：

1. 新增 `src/player/shadow.gd`：脚下椭圆阴影，向下打射线找地面，按离地高度淡出（alpha 0.34→0）并收缩（scale 1.0→0.45）。**`z_index` 必须 ≥ 1**，因为草皮顶是 0、地形是 -1，阴影放 -2 会被地形挡住看不见（我第一版就是这么错的）。
2. 新增 `tools/add_contact_shadow.py`：把每帧脚底 2 行按 42% 混合 `#12142A` 压暗，`#7B8699` → `#4E566A`，与地面形成两个明度层次。跳跃的空中帧跳过不处理。

改完脚明显"踩实"了。

### 12. 阴影 z_index 放负值会被地形遮住

第一版写 `z_index = -2`，想着"画在角色下方"，结果地形是 -1、草皮顶是 0，阴影直接被埋掉，诊断时射线命中正常、`visible=true`、`modulate.a=0.55` 全对，就是看不见。

**修正**：`z_index = 1`（高于草皮顶 0，低于角色）。层级约定：背景 -10 / 远景 -5 / 地形 -1 / 草皮顶 0 / 阴影 1 / 角色 2。

### 13. 离屏截图在 Godot 4.7 下不可靠

想"不弹窗截图"试了三条路，全失败：

| 方案 | 结果 |
|---|---|
| `--headless` | `frame_post_draw` 不触发，脚本永久挂起 |
| 窗口移到屏幕外 `(-4000,-4000)` | 交换链不提交，读到多帧叠加 |
| SubViewport 离屏渲染 | 尺寸对（480×270），但精灵不渲染（相机层级问题） |

**结论**：`tools/capture.gd` 默认把窗口缩到 480×270、无边框、不置顶、放屏幕右下角，**不抢焦点**。要看大图用 `-- --show`。日常验证用 `verify_headless.gd`（完全无窗口）。

## 还没做的（按优先级）

1. **闪避**——输入已注册，逻辑没写。有完美闪避的子弹时间设计（0.12s 内闪避 → 0.6s 慢动作），是核心爽点。
2. **攻击判定**——现在只切状态，没有 hitbox，打不到东西。
3. **攻击 / 受击动画**——目前复用 idle，观感上"挥剑没动作"。
4. **顿帧与震屏**——`_emit_attack_feedback()` 是空钩子。
5. **瓦片接入**——`greybox_tiles.png` 生成了但没用上，地形还是脚本里手写的矩形数据。
6. **敌人与 BOSS**——完全没有。

## 下一步建议

**先别加内容，先调手感。** 拿手柄实际跑一趟这个灰盒房，重点感受三件事：

1. 落地那一下够不够"脆"（`GRAVITY_FALL_MUL` 与 `DECEL_GROUND`）
2. 跳跃顶点高度与滞空时间舒不舒服（`JUMP_VELOCITY` 与 `GRAVITY_RISE_MUL`）
3. 转身跟不跟手（`TURN_BOOST`）

动画方面，跑动是 12 fps / 6 帧，如果觉得"脚在原地划"，可以调 `player.tscn` 里 `run` 动画的 `speed`（当前 12.0），或回 `tools/make_animation.py` 加大腿部横移量（当前最大 ±4px）重跑生成。
